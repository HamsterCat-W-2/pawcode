# v0.5 `/init` 项目上下文初始化设计

## 1. 目标

增加交互式 `/init` 命令，扫描当前工作区并生成项目根目录的 `PAWCODE.md`。生成文件直接复用现有项目上下文加载机制，后续每次模型请求都可以得到稳定的项目说明和开发约定。

本功能采用“扫描事实 → 模型生成草稿 → 权限确认 → 原子写入”的流程，生成结果必须是 Markdown，且不能把密钥或环境变量写入上下文文件。

## 2. 范围与非目标

### 范围

- 仅在交互模式支持 `/init`。
- 扫描有限深度的工作区目录和常见项目元数据文件。
- 使用当前已配置的 `ModelAdapter` 生成中文项目上下文。
- 通过 `PermissionManager` 授权后写入 `./PAWCODE.md`。
- `PAWCODE.md` 已存在时默认停止，避免覆盖用户规则。

### 非目标

- 本阶段不自动修改已有 `PAWCODE.md`。
- 不读取 `.env`、密钥文件、证书或私有配置。
- 不执行项目命令，不安装依赖，不修改 Git 元数据。
- 不新增独立的配置格式；生成内容仍是普通 Markdown。

## 3. Module 与 Seam

新增 `ProjectInitializer` Module，向 CLI 暴露少量接口：

```ts
interface ProjectInitializer {
  inspect(): Promise<ProjectSnapshot>
  generate(snapshot: ProjectSnapshot): Promise<string>
  write(content: string): Promise<string>
}
```

它隐藏目录遍历、敏感文件过滤、模型流收集、Markdown 校验和原子写入。CLI 只负责 `/init` 的交互提示、展示结果和调用权限确认。

依赖关系：

```text
/init → ProjectInitializer
             ├─ WorkspaceFiles      读取和写入工作区
             ├─ ModelAdapter         生成上下文草稿
             └─ PermissionManager    授权写入 PAWCODE.md
```

`ProjectInitializer` 不直接依赖供应商 SDK，也不把扫描细节放进 `AgentRuntime`，以保持 Domain/Adapter seam 和现有权限 seam 的 Locality。

## 4. 扫描规则

- 目录最多扫描 3 层，先应用默认生成物目录规则，再应用项目根目录的 `.gitignore`；不把某一种语言的目录名当成唯一标准。
- 元数据采用候选发现而非固定白名单：根目录配置文件、`README*`、锁文件、`*.config.*`、`*config*`、`*.rc`、`*.toml`、`*.yaml`、`*.yml`、`*.ini`、`*.cfg`、`*.lock`、`Dockerfile*`、`Makefile` 和常见 CI 配置都可以成为候选。
- 只读取候选文件，不把所有源文件发送给模型；候选采用评分机制，结合目录位置、文件名通用特征、文件大小和文本内容，而不是依赖固定扩展名集合。
- 文件总输入限制为 120 KiB，单文件限制为 32 KiB。
- 跳过 `.env*`、包含 `secret`、`token`、`password`、`credential`、`private` 的文件名，以及证书和私钥扩展名。
- 只把路径、目录树和经过筛选的文本内容发送给模型。

`.gitignore` 解析采用轻量规则匹配，支持注释、目录规则、通配符和最后一条规则优先；复杂 Git 特殊语义不影响安全性，无法可靠判断时保留路径但仍经过敏感文件过滤。

## 5. 生成和写入流程

1. `/init` 调用 `inspect()` 获取项目快照。
2. 快照交给 `generate()`，模型必须只返回 `PAWCODE.md` 的 Markdown 内容。
3. 如果目标文件已存在，立即返回保护提示，不进入覆盖流程。
4. CLI 展示生成内容摘要，并请求 `write` capability 授权。
5. `write()` 再次确认目标是工作区内的 `PAWCODE.md`，通过 `WorkspaceFiles.write()` 原子写入。
6. 写入成功后提示用户重新运行 `/show-context` 或继续对话即可使用新上下文。

模型失败、输出为空或输出不是 Markdown 时，不进行写入；不会因为生成失败而改变工作区。

## 6. 测试与验收

- 扫描跳过敏感文件和忽略目录。
- 总输入大小和单文件大小受限。
- 模型响应收集正确，空响应和非 Markdown 响应被拒绝。
- 已有 `PAWCODE.md` 不被覆盖。
- 没有写权限时不发生文件写入。
- 授权后只创建工作区根目录的 `PAWCODE.md`。
- `/init` 成功后，`resolveContext()` 能读取生成文件。
- 运行 TypeScript、Prettier、Vitest 和 `git diff --check`。
