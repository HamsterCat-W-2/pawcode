# v0.5 启动性能优化技术方案

## 目标

降低 `paw` 启动到可交互状态之间的固定开销，同时保留配置、上下文和会话恢复的现有语义。优化只针对启动路径，不改变模型协议、权限边界或会话数据格式。

## 方案

### 1. 启动阶段耗时诊断

新增轻量的启动计时器，在 `--verbose-startup` 开启时将以下阶段耗时写入 stderr：配置加载、会话目录创建、会话恢复、上下文解析、Runtime 创建和总耗时。默认关闭，避免污染普通输出和 JSON stdout。

### 2. 模型与工具按需加载

CLI 的检查命令在返回前不加载模型适配器、工具实现和项目初始化器。交互或一次性 prompt 进入 Runtime 创建时，再通过动态 import 加载这些模块；`/init` 仅在执行命令时加载初始化器。

### 3. 延迟创建动态上下文提供器

启动阶段已经得到根目录上下文快照，Runtime 先使用该快照。只有第一次工具调用前才创建 `DynamicContextProvider`，并把启动快照传入，避免重复读取根上下文文件。工具调用后仍按目标路径重新解析上下文。

### 4. 单次扫描恢复中断会话

`recoverInterruptedSessions` 直接遍历会话 JSON 并读取一次记录。当前实现先调用 `list()`，再为状态为 `running` 的记录再次读取，存在重复 I/O；单次读取可以保持损坏记录容错和 PID 存活判断，同时减少恢复阶段开销。

## 验证

- `pnpm format:check`
- `pnpm check`
- `pnpm test`
- `pnpm build`
- `pnpm dev --show-config --verbose-startup`

耗时诊断只用于定位启动瓶颈，不承诺固定毫秒数；首次 `pnpm dev` 仍可能包含 pnpm 和 tsx 的进程启动成本。
