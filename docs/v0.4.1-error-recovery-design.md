# PawCode v0.4.1 错误恢复加固设计

## 1. 目标

v0.4.1 在不引入自动副作用回滚的前提下，提高模型瞬时故障、用户取消、进程异常退出、文件写入中断和终端管道关闭时的可恢复性。

核心原则：

- 自动恢复不能重复执行工具或命令等副作用。
- 已经展示给用户的模型流不能静默重放。
- 会话和文件写入必须先落完整临时文件，再原子替换目标。
- 取消、失败和进程中断是不同状态，恢复后必须能解释上次发生了什么。
- 恢复失败时优先保留原始数据，不能为了“修复”而覆盖损坏证据。

## 2. 会话运行状态

`lastRunStatus` 增加：

- `cancelled`：用户通过 `Esc` 或运行期间 `Ctrl+C` 正常取消。
- `interrupted`：上次进程在 `running` 状态下异常退出，下一次启动时自动修正。

`SessionStore` 启动后扫描当前项目会话，把遗留 `running` 改为 `interrupted`，但保留原 `updatedAt`，避免恢复扫描改变 `--continue` 的排序。

模型流中断前已经产生的文本作为 assistant 消息保存。工具调用只有完整 response 到达后才执行，因此取消不会重放半截工具调用。

## 3. 模型重试

新增 `RetryingModelAdapter`，包装具体供应商 Adapter：

- 默认最多重试 2 次，使用指数退避和小幅随机抖动。
- 只重试 408、429、500、502、503、504、rate limit、overloaded、临时网络断开等明确瞬时错误。
- 认证、权限、参数、上下文超限、模型不存在和用户取消不重试。
- 一旦底层 Adapter 已产生任意流事件，本次请求不重试，避免重复文本和副作用。
- 等待退避期间响应 AbortSignal。

配置：

```dotenv
MODEL_MAX_RETRIES=2
MODEL_RETRY_BASE_DELAY_MS=500
```

## 4. 原子文件写入

`write_file` 和 `apply_patch` 改为同目录临时文件写入、文件 `fsync`、`rename` 原子替换。已有文件尽量保留权限位；失败时清理本次临时文件。

会话文件沿用同目录原子替换，并增加临时文件 `fsync` 与启动时孤立 `.tmp` 清理。目录 `fsync` 采用 best effort：替换已经成功后，目录同步失败不能谎报整次写入失败。

命令和外部程序的副作用不提供自动回滚；超时或取消后明确报告“可能已经产生部分修改”，由 Agent 使用 `git_diff` 检查。

## 5. 取消、权限与终端

- 权限确认接收当前 run 的 AbortSignal；`Esc` 可以取消正在等待的确认。
- `Esc`/运行态 `Ctrl+C` 产生 `cancelled` 事件，不显示为普通系统错误。
- 输入态 `Ctrl+C` 仍退出并打印恢复命令。
- stdout 遇到 `EPIPE` 时正常退出，避免 `pawcode ... | head` 产生未捕获异常。

## 6. 非目标

- 不自动回滚已经运行的命令、Git 或外部系统副作用。
- 不在已输出 delta 后自动重试模型。
- 不实现跨供应商自动故障转移。
- 不保证 `kill -9` 或断电后的绝对持久化；原子替换只保证旧文件或新文件完整存在。
- 不自动修复损坏 JSON；列表跳过，显式恢复报告错误。

## 7. 验收标准

- 遗留 `running` 会话在下次启动时变为 `interrupted`，排序不改变。
- 用户取消记录为 `cancelled`，部分文本可在恢复历史中看到。
- 瞬时模型错误在没有流输出时按上限重试；输出过 delta 后不重试。
- 退避等待可以被 AbortSignal 立即取消。
- 文件写入成功后没有临时文件，写入失败不破坏原目标。
- 权限确认期间 `Esc` 能返回输入提示。
- stdout `EPIPE` 不打印堆栈并以成功状态退出。
- 现有 v0.3/v0.4 测试全部继续通过。

```bash

pnpm check
pnpm test
pnpm build
git diff --check
```
