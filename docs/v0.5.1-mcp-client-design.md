process.cwd()# v0.5.1 MCP Client（stdio）技术设计

## 1. 文档目的

本文说明 PawCode 第一阶段 MCP Client 的实际设计和边界，重点回答：

- MCP Server 配置从哪里读取；
- PawCode 如何启动和初始化 MCP Server；
- MCP 工具如何进入现有 Agent Runtime；
- 工具调用如何经过权限、超时和输出截断；
- Server 或协议异常时，哪些功能继续可用；
- 当前版本明确不做哪些 MCP 能力。

第一阶段只实现 MCP stdio transport。MCP stdio 规定客户端启动 Server 子进程，通过 stdin/stdout 交换逐行 JSON-RPC 消息，Server 的 stderr 只能作为日志通道；stdout 不能混入非 MCP 内容。

协议参考：[MCP stdio transport](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)、[MCP server tools](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。

## 2. 当前版本范围

### 2.1 已实现

- 分层 MCP Server 配置：用户级、项目级、本地级；
- 用户级 Server 的环境变量配置；
- stdio 子进程启动；
- `initialize` 握手；
- `notifications/initialized` 通知；
- `tools/list` 工具发现和分页 cursor；
- `tools/call` 工具调用；
- MCP 工具映射为 PawCode `Tool`；
- MCP 工具命名空间；
- 工具调用权限确认；
- initialize、tools/list、tools/call 共用 Server 超时配置；
- Server 初始化失败隔离；
- JSON-RPC 错误、非法 JSON 和进程退出处理；
- Runtime 结束时关闭 MCP 子进程。

### 2.2 当前不实现

- Streamable HTTP；
- OAuth 和远程授权流程；
- resources、prompts、sampling；
- MCP tasks；
- `notifications/tools/list_changed` 动态刷新；
- Server 之间的依赖关系；
- MCP Server 配置的交互式管理命令；
- 跨 Session 的 MCP Server 进程复用。

## 3. 配置模型

### 3.1 文件层级

MCP 配置沿用 PawCode 现有三层 JSON 配置：

```text
~/.pawcode/config.json                    用户级
<workspace>/.pawcode/config.json          项目级
<workspace>/.pawcode/config.local.json    本地级
```

同名 Server 按用户级 → 项目级 → 本地级覆盖；不同 Server 合并保留。

### 3.2 配置示例

```json
{
  "mcp": {
    "servers": {
      "filesystem": {
        "command": "npx",
        "args": ["-y", "example-mcp-server"],
        "env": {
          "EXAMPLE_MODE": "readonly"
        },
        "enabled": true,
        "timeoutMs": 30000
      }
    }
  }
}
```

字段含义：

| 字段          | 类型     | 默认值  | 含义                                                         |
| ------------- | -------- | ------- | ------------------------------------------------------------ |
| `mcp.servers` | object   | `{}`    | MCP Server 配置集合，key 是 Server 名称                      |
| `command`     | string   | 必填    | 要启动的可执行文件，例如 `node`、`npx`                       |
| `args`        | string[] | `[]`    | 传给 command 的参数数组，不进行 Shell 解析                   |
| `env`         | object   | `{}`    | 传给 Server 的额外环境变量，仅用户级允许配置                 |
| `enabled`     | boolean  | `true`  | 是否启动和发现该 Server 的工具                               |
| `timeoutMs`   | integer  | `30000` | initialize、tools/list、tools/call 的单次超时，最大 600000ms |

### 3.3 配置安全规则

- Server 名称只允许 `[A-Za-z0-9_-]`，长度 1～40；
- `args` 最多 100 项；
- `command` 和 `args` 通过 `spawn(command, args, { shell: false })` 执行；
- 项目级和本地级配置禁止 `mcp.servers.*.env`，防止环境变量凭据进入 Git；
- 用户级 `env` 不会在 `--show-config` 中显示真实值，会统一显示为 `<redacted>`；
- Server 进程会继承 PawCode 当前进程环境，再由用户级 `env` 覆盖同名变量；
- MCP 配置错误会在配置加载阶段失败，不会静默使用不完整配置。

## 4. 模块职责

```text
config-schema.ts
      ↓ schema 校验
config-loader.ts
      ↓ 三层合并、环境变量来源限制
config.ts
      ↓ Runtime 配置投影
McpStdioClient
      ↓ 子进程、JSON-RPC、超时、生命周期
McpTool
      ↓ MCP Tool → PawCode Tool
ToolRegistry
      ↓ 工具查找、权限调用、输出截断
AgentRuntime
      ↓ 模型请求和工具循环
```

### 4.1 `McpStdioClient`

职责：

1. 使用 `spawn` 启动单个 MCP Server；
2. 监听 stdout，按换行拆分 JSON-RPC 消息；
3. 使用 request ID 将响应匹配到 pending request；
4. 为每个请求建立超时计时器；
5. 解析 JSON-RPC `result` 或 `error`；
6. 处理 Server 的 `error`、`close` 和非法 stdout；
7. 在关闭时结束 stdin、终止子进程并 reject 未完成请求。

当前一个 Client 对应一个 Server 子进程，不跨 Runtime 复用。

### 4.2 `McpTool`

每个 MCP tool description 映射成一个 PawCode `Tool`：

```text
MCP Server: filesystem
MCP tool:  read_file
PawCode:   mcp_filesystem_read_file
```

映射规则：

- `name`：`mcp_<serverName>_<remoteToolName>`；
- `description`：使用 MCP description，没有时生成默认描述；
- `inputSchema`：直接作为 `ToolDefinition.function.parameters`；
- 参数：PawCode 收到 JSON 字符串后解析为对象，再发送给 MCP `tools/call`；
- 返回值：提取 MCP `content` 中的 text block，多个 text block 用换行拼接；
- MCP `isError: true` 转换为工具错误文本。

## 5. MCP 生命周期

### 5.1 Runtime 创建阶段

`createRuntimeBundle()` 的流程如下：

```text
读取 PawCode 配置
      ↓
创建内置 ModelAdapter 和 Tool
      ↓
按 enabled 过滤 MCP Server
      ↓
逐个 spawn MCP Server
      ↓
发送 initialize request
      ↓
收到 InitializeResult
      ↓
发送 notifications/initialized
      ↓
发送 tools/list
      ↓
创建 MCP Tool 实例
      ↓
加入 ToolRegistry
      ↓
创建 AgentRuntime
```

Server 按配置顺序逐个加载。某个 Server 失败时记录 stderr 诊断并跳过该 Server，内置工具和其他成功 Server 仍然可用。

### 5.2 initialize 请求

PawCode 发送：

```json
{
  "jsonrpc": "2.0",
  "id": "request-id",
  "method": "initialize",
  "params": {
    "protocolVersion": "2025-06-18",
    "capabilities": {},
    "clientInfo": {
      "name": "pawcode",
      "version": "0.5.0"
    }
  }
}
```

收到成功响应后发送通知：

```json
{
  "jsonrpc": "2.0",
  "method": "notifications/initialized",
  "params": {}
}
```

### 5.3 工具发现

PawCode 调用 `tools/list`。如果响应提供 `nextCursor`，客户端继续请求下一页，直到没有 cursor。无效的 tool description 不进入 ToolRegistry。

### 5.4 Runtime 结束阶段

- 一次性 prompt 执行结束后关闭该 Runtime 的所有 MCP Client；
- 交互模式 `/exit`、Ctrl+C 或 readline 结束时关闭当前 MCP Client；
- `/new`、`/resume`、`/branch` 切换会话前关闭旧 Runtime 的 MCP Client；
- close 时结束 stdin 并终止子进程；
- 清理失败不回滚已完成的用户操作，只保留进程级错误诊断。

## 6. 工具调用和权限链路

```text
模型返回 tool_call
      ↓
AgentRuntime
      ↓
ToolRegistry.execute("mcp_filesystem_read_file", argumentsJson)
      ↓
McpTool.permissionRequest()
      ↓
PermissionManager.authorize({ capability: "execute", ... })
      ↓
允许？ ── 否 → 返回“权限被拒绝”，不发送 MCP 请求
  │
  是
  ↓
McpStdioClient.callTool()
      ↓
MCP Server tools/call
      ↓
content text → ToolRegistry 输出截断 → AgentRuntime
```

MCP 工具统一使用 `execute` capability，资源标识为：

```text
mcp://<serverName>/<toolName>
```

MCP Server 来自外部进程并不意味着它可以绕过 PawCode 权限；所有调用都必须进入 `ToolRegistry` 的统一授权入口。

## 7. 超时和错误语义

| 场景                  | 行为                                               |
| --------------------- | -------------------------------------------------- |
| spawn 失败            | 当前 Server 加载失败，记录诊断，内置工具继续运行   |
| initialize 超时       | 关闭当前 Server，跳过当前 Server                   |
| tools/list 超时       | 关闭当前 Server，跳过当前 Server                   |
| tools/call 超时       | 当前工具返回失败文本，其他工具继续可用             |
| Server stdout 非 JSON | 当前 pending 请求失败，Server 不再提供可靠工具服务 |
| JSON-RPC error        | 转换为 `MCP <code>：<message>` 工具错误            |
| Server 非正常退出     | 未完成请求失败，后续调用返回 Server 已关闭         |
| MCP `isError: true`   | 保留为工具错误结果，不当作 PawCode 进程崩溃        |
| 返回非 text content   | 使用 `[<type> 内容]` 占位，不猜测内容              |
| 工具输出过长          | 由 ToolRegistry 统一截断                           |

错误信息不能打印完整环境变量、API Key 或其他配置秘密。

## 8. 配置与调用示例

### 8.1 用户级配置

```bash
mkdir -p ~/.pawcode
chmod 700 ~/.pawcode
```

`~/.pawcode/config.json`：

```json
{
  "model": {
    "name": "your-model"
  },
  "mcp": {
    "servers": {
      "demo": {
        "command": "node",
        "args": ["/absolute/path/to/demo-mcp-server.js"],
        "env": {
          "DEMO_MODE": "readonly"
        },
        "timeoutMs": 10000
      }
    }
  }
}
```

### 8.2 启动验证

```bash
pnpm dev --show-config --json
pnpm dev --show-context --json
pnpm dev --verbose-startup
```

检查点：

- `--show-config` 中 MCP 环境变量显示 `<redacted>`；
- `--show-context` 不启动模型，但普通 Runtime 会在创建时加载 MCP；
- 启动日志中若 Server 失败，应看到 `配置警告：MCP Server ... 加载失败`；
- 进入交互后，模型工具列表应出现 `mcp_<server>_<tool>`。

## 10. 后续演进

完成 stdio 稳定性后，再按以下顺序推进：

1. MCP 工具 schema 更严格校验和更明确的诊断；
2. `notifications/tools/list_changed` 动态更新；
3. Streamable HTTP transport；
4. HTTP 场景的 OAuth 和 Server 信任策略；
5. resources、prompts、sampling 和 tasks。

每次扩展都必须复用现有 `ToolRegistry`、`PermissionManager`、输出截断和上下文刷新机制，不能为 MCP 另建一套权限入口。
