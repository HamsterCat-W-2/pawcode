# v0.5 `/init` 扫描诊断技术方案

## 目标

让 `/init` 和 `/init --full` 在生成前明确说明扫描范围与信息损失，帮助用户判断生成结果是否完整。诊断只展示扫描事实，不把诊断文本写入 Session 历史或模型上下文之外的额外状态。

## 诊断内容

`ProjectSnapshot` 增加扫描统计：扫描模式、发现文件数、过滤后文件数、读取文件数、分块数，以及项目树是否被截断。已有 `ProjectDiagnostic` 继续记录具体文件和原因，覆盖：

- `.gitignore` 或安全规则跳过的文件不作为模型输入；
- 二进制、空文件、敏感内容和读取失败；
- 快速扫描的候选文件、读取字节或项目树达到上限；
- 完整扫描的文件数、单文件大小或分块数达到上限。

## CLI 展示

`/init` 在调用模型前打印一段统一的扫描报告：模式、统计数字和诊断条目。没有诊断时打印“未发现跳过或截断项”。`/init --full` 保留现有分块进度，并在扫描报告中显示分块数量。

诊断输出只走人类可读 CLI；未来接入 NDJSON 时复用 `ProjectInitEvent`，不改变模型请求和权限流程。

## 兼容性与边界

- 不改变已有 `PAWCODE.md` 存在时的保护行为。
- 不放宽敏感文件、工作区边界或 `.gitignore` 过滤规则。
- 统计字段是附加信息，旧的 `ProjectInitializer.generate` 调用仍可工作。
- 诊断原因不包含文件内容、凭据或环境变量值。

## 验证

- 覆盖快速扫描的读取上限、文件树截断和读取失败；
- 覆盖完整扫描的二进制、敏感内容、单文件截断和分块上限；
- 验证 `pnpm format:check`、`pnpm check`、`pnpm test` 和 `pnpm build`。
