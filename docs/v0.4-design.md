# PawCode v0.4 技术设计

## 1. 目标与非目标

v0.4 增加项目级会话持久化与恢复、长上下文压缩和严格 NDJSON 输出，使 PawCode 可以跨进程续聊并被脚本稳定调用。

本版本不实现云同步、跨项目会话迁移、交互式 JSON 权限协议、MCP 或子 Agent。

## 2. 项目级会话

会话入口参考 [Claude Code 官方会话语义](https://code.claude.com/docs/en/sessions)：continue 恢复最近会话，resume 负责选择或精确恢复，fork 从恢复点创建新 ID，rename 提供稳定名称。PawCode 第一版选择器使用编号列表，不实现 Claude Code 的跨 worktree 搜索和快捷键界面。

会话保存在当前工作区：

```text
.pawcode/
└── sessions/
    └── <session-id>.json
```

`.pawcode/` 已被 Git 忽略。`SessionStore` 在创建时保存工作区 `realpath`，加载时再次比较；即使有人手工复制会话文件，也不能在不同项目恢复。分支信息只作为元数据和提示，不作为项目身份，因为同一项目切换分支是正常行为。

### 2.1 Schema v1

```ts
interface SessionRecord {
  schemaVersion: 1
  id: string
  title: string
  name?: string
  parentSessionId?: string
  createdAt: string
  updatedAt: string
  workspace: string
  gitBranch?: string
  provider: string
  model: string
  messages: Message[]
  cumulativeUsage?: ModelUsage
  lastRunStatus: 'idle' | 'running' | 'completed' | 'failed'
  compactionCount: number
}
```

磁盘数据必须经 Zod 校验。API Key、环境变量和权限允许规则不得写入会话。`providerData` 作为消息的一部分保存，但必须可以被 `JSON.stringify`；失败时整个保存操作报错，不能静默丢失供应商连续性信息。

### 2.2 写入与恢复

- 保存使用同目录临时文件、`writeFile` 和 `rename` 原子替换。
- 文件权限使用 `0600`。
- 临时文件在失败时通过 `unlink` 清理。
- `--continue/-c` 恢复最近更新的会话；没有会话时明确失败，不隐式新建。
- `--resume/-r` 无参数打开项目会话选择器，带参数时按会话 ID 或名称精确恢复。
- `--name/-n` 为会话设置稳定名称，交互内 `/rename [name]` 可修改名称。
- `--fork-session` 与 continue/resume 一起使用，复制历史并创建新 ID；交互内 `/branch [name]` 提供相同行为，且会话权限规则不继承。
- `--list-sessions` 列出当前项目会话。
- 交互命令提供 `/new`、`/sessions`、`/resume [id|name]`、`/rename [name]` 和 `/branch [name]`。
- 恢复默认沿用会话中的 provider/model；显式 CLI 参数可以覆盖，但会提示连续性风险。只有 `api + provider + model` 完全一致时 Adapter 才重放原始 `providerData`；任一项变化时使用 PawCode `content + tool_calls` 重建可移植消息。

Runtime 在用户消息、assistant 完整消息、每个 tool result 和清空会话后触发保存回调。CLI 在 run 开始、完成或失败时更新状态与累计 usage。

## 3. 上下文预算与压缩

### 3.1 Token 估算

`ModelAdapter` 暴露可选的 `contextWindow`；`PiAiModelAdapter` 从选中模型元数据提供该值。文本估算取字符数与 UTF-8 字节数除以 4 的较大值，并计入角色、工具参数和固定消息开销。这不是计费数据，只用于提前触发压缩。

配置：

```dotenv
CONTEXT_COMPACT_THRESHOLD=0.8
CONTEXT_KEEP_RECENT_TOKENS=20000
```

当估算输入达到 `contextWindow × threshold` 时触发压缩。

### 3.2 安全切分

除首条 system prompt 外，消息按完整用户轮次分组：从一条 user 消息开始，到下一条 user 消息之前结束。已有历史摘要作为旧历史参与下一次压缩。只在组边界切分，因此 assistant tool call 和对应 tool result 不会被拆开。

保留：

- 首条 system prompt。
- 最近若干完整轮次，总量不超过 keep recent 预算。
- 当前最新用户轮次。

较早轮次发送给同一个 `ModelAdapter` 生成结构化文本摘要，摘要要求保留用户目标、架构决定、文件修改、命令/测试结果、错误和未完成事项。摘要请求不提供工具。若摘要模型失败，保留原消息并继续当前请求，不能为压缩而丢失历史。

摘要以带固定前缀的 system 消息加入 PawCode Domain。摘要响应的 usage 计入本次 run，压缩后立即保存会话并增加 `compactionCount`。CLI/JSON 收到 `context_compacted` 事件。

上下文压缩只处理下一次请求的输入历史，不截断正在输出的回答。单次回答达到模型上限时保留已生成文本，并通过 stop reason 显示 `length`；v0.4 不自动续写。

## 4. NDJSON 输出

```bash
paw --json "检查项目"
```

stdout 每行都是一个带 `version: 1` 的 JSON 事件，不输出标题、Emoji、ANSI 颜色或交互提示。人类可读诊断写 stderr。运行事件来自 `AgentEvent` 的独立序列化层，Runtime 不依赖 JSON。

示例：

```json
{"version":1,"type":"turn_started","turn":1}
{"version":1,"type":"text_delta","text":"正在检查"}
{"version":1,"type":"completed","stopReason":"stop","usage":{"totalTokens":1200}}
```

`Error` 转换为 `{ "message": string }`，工具参数保持 JSON 字符串以确保事件总能序列化。`--list-sessions --json` 输出一个 `sessions` 事件。

JSON 是非交互模式：

- 没有 allow 参数时，写入和命令调用返回结构化权限拒绝工具结果。
- `--allow-write` 和 `--allow-command <prefix>` 提供预授权。
- 不读取 stdin 获取权限，不输出 `permission_required` 后等待回复。
- `--json` 没有 prompt 且不是列表操作时直接失败。
- JSON 模式使用无参数 `--resume` 时拒绝，因为选择器需要交互；必须提供 ID 或名称。

人类可读模式默认隐藏成功工具的参数和结果长度，减少只读工具造成的输出噪声；工具失败始终显示。`--verbose` 用于恢复完整工具调用明细，不改变 NDJSON 事件流。

交互启动页使用内置的 `PAWCODE` ASCII Banner，不增加运行时依赖。仅在 stdout 是 TTY 时展示；宽度不足时降级为紧凑标题，设置 `NO_COLOR` 时保留布局但移除 ANSI 色彩。单次 prompt、重定向和 NDJSON 模式不输出 Banner。

## 5. 失败与安全

- 损坏、未知 schema、工作区不匹配的会话拒绝加载并给出明确错误。
- Session ID 只允许安全文件名字符，阻止路径穿越。
- 保存内容不得出现配置对象或 API Key。
- 会话保存失败视为运行失败，避免用户误以为已经持久化。
- 压缩失败不破坏原消息。
- JSON 模式的 stdout 始终保持可逐行 `JSON.parse()`。
- v0.3 的路径、权限和命令安全边界保持不变。

## 6. 验收标准

- 不同项目不能列出或恢复彼此会话。
- 会话文件原子写入、权限为 `0600`，损坏文件不会导致进程崩溃。
- 退出并恢复后，消息和 `providerData` 可继续多轮工具调用。
- 会话文件不含 API Key。
- 长会话在安全轮次边界压缩，并保留最近历史与工具调用对。
- 压缩 usage 计入统计，失败时保留原历史。
- `--json` 每个 stdout 行都能解析，且没有人类装饰输出。
- 非交互副作用默认拒绝，显式 allow 规则仍有效。
- v0.3 测试继续通过。
