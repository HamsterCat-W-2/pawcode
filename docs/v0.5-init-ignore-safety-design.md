# v0.5 `/init` 忽略与符号链接安全方案

## 目标

在不扩大模型输入和工作区访问范围的前提下，提高 `/init` 对常见 `.gitignore` 语义的兼容性，并明确符号链接的安全边界。

## `.gitignore` 规则

保留轻量、无外部命令依赖的解析器，但补齐以下行为：

- 注释、空行、转义的 `#`、`!` 和空格；
- 根路径规则与任意目录层级规则的区别；
- `*`、`?`、`**`，包括 `**/name` 匹配根目录和嵌套目录；
- 目录规则对目录本身及其后代文件生效；
- 规则按文件顺序应用，最后一条匹配规则决定忽略或恢复。

无法完整模拟 Git 的规则不应放宽安全边界：敏感路径和默认安全目录仍然优先跳过。

## 符号链接

`WorkspaceFiles.walk()` 不跟随符号链接，因此 `/init` 的目录扫描不会读取链接目标。对用户显式指定的读取、列表和写入路径，继续使用 `realpath` 后的工作区边界检查：

- 链接到工作区外：拒绝；
- 链接到工作区内：允许显式读取，但自动扫描仍不跟随；
- 写入链接：检查最终真实路径，不允许越过工作区或修改 `.git`。

## 验证

新增测试覆盖复杂 glob、反选、转义字符、嵌套目录、工作区内链接和工作区外链接。验证命令保持：`pnpm format:check`、`pnpm check`、`pnpm test`、`pnpm build`。
