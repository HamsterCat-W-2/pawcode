# v0.5 `/init --update` 安全更新技术方案

## 目标

在用户明确调用 `/init --update` 时更新 PawCode 自动维护的项目上下文，同时完整保留 `PAWCODE.md` 中的用户手写内容。

## 管理区格式

首次 `/init` 生成的内容包在唯一管理区中：

```md
<!-- pawcode:managed:start -->

自动生成的项目上下文
<!-- pawcode:managed:end -->
```

管理区外的内容属于用户内容，更新时原样保留。更新文件必须恰好包含一对管理标记；缺少标记或存在多对标记时拒绝更新，避免猜测用户意图。

## 流程

1. `/init --update` 扫描项目并生成新的自动维护内容。
2. 读取现有 `PAWCODE.md`，校验唯一管理区并替换管理区内容。
3. CLI 展示变更预览。
4. 通过 `PermissionManager` 请求 `write` 权限。
5. 使用 `WorkspaceFiles` 原子写入；用户拒绝、模型失败或标记非法时不修改文件。

普通 `/init` 和 `/init --full` 仍然不会覆盖已有文件；`--update` 是显式 opt-in。支持 `/init --full --update`，完整扫描只影响新生成的管理区内容。

## 安全边界

- 只允许更新工作区根目录的 `PAWCODE.md`。
- 不执行命令，不修改 Session 历史或 Git 元数据。
- 预览和错误信息不输出文件中的凭据内容以外的额外敏感信息；模型输入继续使用现有扫描过滤规则。
- 更新失败和权限拒绝保持原文件不变。

## 验证

- 首次 `/init` 自动加入管理区。
- 管理区更新时保留前后用户内容。
- 缺少标记、多对标记和已有文件的普通 `/init` 均拒绝修改。
- 权限拒绝、模型失败和原子写入路径均不破坏原文件。
