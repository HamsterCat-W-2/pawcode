# PawCode v0.5 技术设计：工具目标路径的动态上下文

## 1. 背景与目标

当前 v0.5 已能在启动时加载用户级、工作区根级和指定目标路径的 `PAWCODE.md`/`AGENTS.md`，也能解析路径规则并在 Runtime 请求中注入 system prompt。

本阶段补齐运行时能力：当 Agent 通过工具读取、搜索、修改或进入某个路径时，下一次模型请求应自动携带该目标路径沿途的上下文规则。

例如：

```text
PAWCODE.md
src/PAWCODE.md
src/tools/AGENTS.md
src/tools/run-command-tool.ts
```

当工具目标是 `src/tools/run-command-tool.ts` 时，下一轮模型请求应包含根目录、`src/` 和 `src/tools/` 的有效规则，并应用该路径的 `pathRules`。

### 1.1 交付范围

- 为工具调用提供目标路径提取接口。
- 在工具执行前解析目标路径上下文，以便路径规则可以阻止被禁用的工具。
- 在工具执行后把最新上下文快照用于下一次模型请求。
- 多目标工具调用时合并目标路径的上下文，结果顺序确定且去重。
- 当上下文文件 hash 或配置变化导致有效 system prompt、来源、禁用工具或诊断变化时发出刷新事件，即使目标路径没有变化。
- 输出结构化 `context_updated`/`context_update_failed` 事件。
- 动态上下文正文不写入 SessionRecord；只在事件和诊断中输出来源、hash 和规则变化。

### 1.2 非目标

- 不根据任意 Shell 命令字符串猜测命令访问了哪些文件。
- 不在工具执行过程中修改上下文文件或配置文件。
- 不因为上下文加载失败而自动重试或回滚工具副作用。
- 不让项目上下文绕过 `ToolRegistry`、`PermissionManager`、工作区边界或危险命令拒绝。
- 不在本阶段实现跨进程缓存、文件监听或自动记忆。

## 2. 模块与 seam

动态上下文应通过一个深模块隐藏路径发现、文件 hash、来源合并和失败兼容逻辑。调用方只需要提供工具调用和当前快照。

### 2.1 外部接口

```ts
interface RuntimeContextProvider {
  initial(): Promise<ResolvedContext>
  beforeToolCall(call: ToolCall): Promise<ContextDecision>
  current(): ResolvedContext
}

interface ContextDecision {
  context: ResolvedContext
  targetPaths: string[]
  disabled: boolean
  diagnostics: string[]
}
```

接口约束：

- `initial()` 在 Runtime bundle 创建时调用，返回工作区根级上下文。
- `beforeToolCall()` 在每个工具真正执行前调用；它必须先完成路径校验和上下文解析，再决定当前工具是否被路径规则禁用。
- `current()` 返回不可变快照，不能暴露内部可变数组或允许调用方修改来源内容。
- 同一个目标路径和相同文件 hash 必须得到相同 fingerprint；未发生变化时返回当前快照，避免重复组装 system prompt。
- 上下文加载失败时保留上一个可用快照，并把失败原因放入 `diagnostics`；不能让工具副作用因为非关键的上下文 warning 自动回滚。

### 2.2 seam 位置

```text
Tool definition
  ↓ target extractor
ToolRegistry
  ↓ ToolCall + target paths
RuntimeContextProvider
  ↓ ContextDecision
AgentRuntime
  ├── ToolRegistry.execute(..., dynamic restrictions)
  └── next model request uses current context snapshot
```

`AgentRuntime` 不解析工具参数、不读取文件、不实现 glob 匹配。`ContextResolver` 不执行工具、不做权限确认。`ToolRegistry` 仍是唯一的工具执行 seam。

## 3. 工具目标路径协议

在 `Tool` 接口增加可选的目标提取能力：

```ts
interface Tool {
  // 返回工作区相对路径；解析失败时返回诊断，不得猜测或扩大范围。
  contextTargets?(argumentsJson: string): ContextTarget[]
}

interface ContextTarget {
  path: string
  kind: 'file' | 'directory' | 'cwd'
}
```

实现规则：

| 工具          | 目标来源         | 规则                                |
| ------------- | ---------------- | ----------------------------------- |
| `read_file`   | `path`           | 文件路径                            |
| `write_file`  | `path`           | 文件路径，先校验再执行              |
| `apply_patch` | `path`           | 文件路径，先校验再执行              |
| `list_files`  | `path`           | 目录路径，缺省为工作区根            |
| `grep`        | `path`           | 文件或目录路径，缺省为工作区根      |
| `run_command` | `cwd`            | 只使用显式 cwd，不分析 command/args |
| `git_diff`    | `cwd` 或工作区根 | 只读取当前工作区上下文              |

无路径或 JSON 参数无法解析时使用工作区根级上下文，并记录 `target_unresolved` 诊断。不得从命令文本、文件内容或模型自然语言中推断隐藏路径。

### 3.1 多目标与排序

- 一个工具调用只应产生有限目标；目标数量超过 16 时拒绝动态解析并回退到当前快照。
- 路径先经过 `WorkspaceFiles` 同等的 lexical、realpath 和符号链接边界校验。
- 多个目标统一转换为工作区相对 POSIX 路径、排序后去重。
- 合并上下文时按用户级、工作区根级、目录深度、目标路径排序；同一文件只加载一次。
- 多目标下 `disabledTools` 使用并集：任一目标路径禁用当前工具，则当前工具调用被拒绝，防止通过多目标绕过规则。

## 4. 工具执行生命周期

一次带工具调用的模型轮次按以下顺序执行：

```text
模型返回完整 ToolCall
        ↓
RuntimeContextProvider.beforeToolCall()
        ↓
目标解析 + 路径安全校验 + 上下文 fingerprint
        ↓
如果当前工具被目标规则禁用 → 不执行工具，返回结构化拒绝结果
        ↓
ToolRegistry → PermissionManager → Tool.execute()
        ↓
保存 tool result
        ↓
下一轮模型请求使用 decision.context.systemPrompt
```

重要控制流：

1. 上下文解析发生在权限确认之前，但它不能替代权限确认。
2. 动态规则拒绝发生在副作用执行之前；即使模型已经发出 ToolCall，也不能执行被路径规则禁用的工具。
3. 工具目标路径的安全校验必须与实际工具使用的工作区校验一致，不能出现“上下文认为安全、工具认为越界”的分歧。
4. 工具执行失败仍然要把失败 result 返回模型；上下文更新失败只作为诊断，不覆盖真实工具错误。
5. 每次新的模型请求都从 Runtime 当前快照组装消息；SessionRecord 仍只保存 PawCode system prompt、用户消息、assistant 消息和 tool result。

## 5. Runtime 接入

`AgentRuntimeOptions` 增加一个 `contextProvider?: RuntimeContextProvider`，不把 `ContextResolver` 直接暴露给 Runtime。

Runtime 内部只增加三类动作：

- 初始化时取得 `initial()`；
- 执行每个 ToolCall 前调用 `beforeToolCall()`；
- 将当前 `ResolvedContext.systemPrompt` 覆盖到下一次模型请求的 system message。

上下文切换不得修改 `this.messages`，也不得触发 `onMessagesChanged`。这样动态上下文不会：

- 出现在会话历史回放中；
- 被 `ContextCompactor` 当作旧对话摘要；
- 写入 session JSON 或 providerData；
- 因项目私有规则变化而污染跨进程恢复。

### 5.1 工具定义过滤与执行保护

`ToolRegistry` 需要把动态禁用集合作为一次执行上下文的一部分：

```ts
execute(name, argumentsJson, context, restrictions?): Promise<string>
definitions(restrictions?): ToolDefinition[]
```

下一次模型请求的工具定义应过滤当前上下文禁用的工具；执行入口还必须再次检查禁用集合，防止模型调用旧快照中的工具名。

## 6. 事件和诊断

新增供应商无关的 AgentEvent：

```ts
type ContextUpdatedEvent = {
  type: 'context_updated'
  targetPaths: string[]
  addedSources: ContextSource[]
  removedSources: ContextSource[]
  disabledTools: string[]
}

type ContextUpdateFailedEvent = {
  type: 'context_update_failed'
  targetPaths: string[]
  error: Error
  retainedPreviousContext: true
}
```

事件规则：

- fingerprint 未变化时不发 `context_updated`；工具目标路径本身不参与 fingerprint，避免不同文件但相同有效上下文时每轮重复输出。
- 人类输出只显示来源数量、目标路径和禁用工具；不默认打印指令正文。
- `--verbose` 可以显示来源 hash 的前 12 位。
- JSON 模式通过现有 `toJsonEvent()` 序列化，错误只输出 `error.message`。
- 事件不得包含 API Key、完整配置对象或未经用户主动请求的上下文正文。

## 7. Fingerprint 与一致性

`ResolvedContext` 增加内部 fingerprint，至少由以下内容组成：

```text
workspace realpath
目标路径集合
配置层级 hash
已加载指令文件的绝对路径 + sha256
pathRules 匹配结果
loader 版本
```

比较 fingerprint 时必须使用规范化后的路径和排序后的集合。文件不存在、读取失败或超限时也要将诊断状态纳入 fingerprint，避免错误被旧成功结果永久掩盖。

配置或指令文件在工具运行期间发生变化时：

- 当前工具继续使用执行前已经确认的 `ContextDecision`；
- 工具完成后下一次模型请求重新计算；
- 不中断已经开始的外部命令，不尝试回滚副作用；
- 通过 `context_updated` 或 `context_update_failed` 明确呈现变化。

## 8. 安全边界

- 目标路径只接受工作区相对路径；绝对路径、`..` 和符号链接逃逸拒绝或回退到安全快照。
- `run_command` 只解析 cwd，不从参数推断任意文件访问范围。
- 动态上下文不能解除 `PermissionManager` 的 allow/ask/deny，也不能解除危险程序、Shell 选项和破坏性 Git 子命令拒绝。
- `disabledTools` 只能减少工具集合；不存在“上下文允许工具”的配置语义。
- 指令文件正文中的“忽略系统提示”“自动执行命令”等内容仍只是模型上下文，不能改变应用层控制流。
- 上下文读取失败默认保留上一个安全快照；首次初始化失败则只使用内置 system prompt。
- 事件、诊断和会话保存必须经过敏感值 redaction。

## 9. 测试规划

### 9.1 ContextProvider 单元测试

- 根目录到深层目录的加载顺序；
- `PAWCODE.md` 与 `AGENTS.md` 同目录优先级；
- 文件内容 hash 变化触发刷新；
- fingerprint 相同不重复生成更新事件；
- 目标路径排序、去重和最多 16 个目标限制；
- 文件、目录、cwd 和缺省路径的目标提取；
- 绝对路径、`..`、符号链接和工作区外路径；
- 配置/指令读取失败保留上一快照。

### 9.2 Runtime/ToolRegistry 测试

- 工具执行前动态规则可以阻止被禁用工具；
- 权限确认仍在动态规则之后继续生效；
- 工具 result 返回后下一次模型请求使用新 system prompt；
- 动态上下文不触发 `onMessagesChanged`，不进入 session snapshot；
- 多目标禁用集合使用并集；
- 工具失败和上下文更新失败不会互相覆盖。

### 9.3 CLI/JSON 回归测试

- `context_updated` 和 `context_update_failed` 输出合法 NDJSON；
- 默认人类输出不泄露上下文正文和 API Key；
- 恢复会话后重新计算当前文件上下文；
- 现有 v0.5 配置、权限、会话、压缩和 74 个测试继续通过。

## 10. 分阶段实施

1. **阶段 A：目标提取**
   - 为内置工具增加 `contextTargets()`；为 `ToolRegistry` 增加统一目标解析 seam。
2. **阶段 B：RuntimeContextProvider**
   - 封装 `ContextResolver`、fingerprint、快照保留和失败策略。
3. **阶段 C：Runtime 接入**
   - 在 ToolCall 执行前刷新上下文，动态过滤工具定义并注入下一轮模型请求。
4. **阶段 D：事件、CLI 和回归**
   - 增加结构化事件、人类渲染、JSON 测试和完整验证。

编码前的验收条件：

- 任意工具目标路径都不能绕过工作区安全检查。
- 动态上下文只影响下一次模型请求，不污染会话消息。
- 被路径规则禁用的工具在执行前被拒绝，不能依靠旧工具定义绕过。
- 上下文故障不会自动回滚已经发生的命令副作用。
- `pnpm format:check && pnpm check && pnpm test && pnpm build` 全部通过。
