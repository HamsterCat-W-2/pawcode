# v0.5 持久化记忆技术方案

## 目标

为 PawCode 增加跨会话的用户级和项目级持久化记忆。记忆独立于 Session 消息历史，通过上下文解析器在模型请求前注入；用户可以查看、添加、删除和清空记忆。

## 存储格式

```text
~/.pawcode/memory.json       用户级记忆
.pawcode/memory.json         项目级记忆
```

文件使用版本化 JSON：

```json
{
  "version": 1,
  "entries": [
    {
      "id": "mem_...",
      "content": "项目使用 pnpm，不要运行 npm install。",
      "createdAt": "2026-07-22T00:00:00.000Z",
      "updatedAt": "2026-07-22T00:00:00.000Z"
    }
  ]
}
```

用户级记忆先于项目级记忆注入；同一条记忆不会写入 SessionRecord，也不会参与历史压缩。每个作用域限制条目数量、单条大小和总文件大小，拒绝疑似 API Key、Token、密码、私钥等敏感内容。

## CLI

```text
/memory
/memory add <内容>                 默认写入项目级
/memory add --user <内容>          写入用户级
/memory remove <id> [--user]
/memory clear [--user|--project]
```

读取不需要权限；新增、删除和清空需要现有 `PermissionManager` 的 `write` 授权。默认 `/memory clear` 只清空项目级，避免误删全局记忆。

## 上下文集成

`resolveContext()` 加载两级记忆并将其作为独立 `ContextSource` 注入 system prompt。记忆文件变化会进入上下文 fingerprint，因此工具目标路径刷新前会重新读取最新记忆。损坏或超限的记忆文件只产生诊断，不阻断普通项目上下文加载。

## 安全与验证

- 用户记忆目录固定为 `~/.pawcode`，项目记忆固定为当前工作区 `.pawcode`。
- 写入使用现有原子文件替换，用户文件使用 `0600` 权限。
- 不支持任意路径参数，ID 只允许精确匹配。
- 测试覆盖分层加载、原子写入、敏感内容拒绝、损坏文件容错、CLI 操作和 Session 不污染。
