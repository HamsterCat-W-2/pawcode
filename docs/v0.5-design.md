# PawCode v0.5 技术设计：项目上下文与分层配置

## 1. 版本目标

v0.5 为 PawCode 增加两类基础能力：

1. 自动发现并加载项目指令文件，使 Agent 在进入项目后能理解项目约定、安全边界和工作流。
2. 建立用户级、项目级、本地级配置的分层加载、覆盖和校验规则。

这两个能力必须共享同一套来源、优先级、路径范围和诊断机制，避免后续 MCP、Hooks、Skills 分别实现互不兼容的配置系统。

### 1.1 本版本交付范围

- 加载 PawCode 自有上下文文件，暂定文件名为 `PAWCODE.md`。
- 默认以兼容模式支持 `AGENTS.md`，但不自动复制或改写该文件。
- 支持用户级、项目级和本地级配置。
- 配置文件使用 JSON，经过 Zod schema 校验。
- 支持按工作区相对路径匹配的规则。
- 提供 CLI 命令检查当前加载的上下文、配置来源和覆盖结果。
- 将最终有效上下文注入模型请求的 system prompt，而不是写入 PawCode message 历史。
- 对上下文文件和配置文件执行大小、路径、权限和敏感字段保护。

### 1.2 非目标

- 不在 v0.5 实现 MCP、Hooks、Skills 或子 Agent。
- 不实现自动记忆、自动修改项目指令文件或远程同步。
- 不把整个项目文件内容自动加入上下文。
- 不允许项目级或本地级配置保存模型 API Key；用户级配置可以保存凭据，但必须使用受限文件权限。
- v0.5 不再读取 `.env` 或模型相关环境变量；现有 `.env` 配置需要迁移到用户级配置文件。
- 不改变现有会话 schema；上下文来源通过运行时重建，不保存密钥和完整配置快照。

## 2. 设计原则

### 2.1 来源可追踪

每一条生效规则都必须保留来源信息：来源级别、绝对路径、相对路径范围、加载顺序和是否被覆盖。CLI 诊断和错误信息不得只展示最终值而隐藏来源。

### 2.2 显式优先级

非敏感配置默认优先级从低到高为：

```text
内置默认值
  < 用户级配置
  < 项目级配置
  < 本地级配置
  < CLI 显式参数
```

敏感配置单独遵循更严格的来源规则：

```text
用户级配置中的凭据 < CLI 显式参数（仅当未来支持临时凭据参数时）
```

项目级和本地级配置不能覆盖或删除用户级凭据。这样项目可以声明 `provider` 和 `model`，但不能要求开发者把密钥写进项目文件。

### 2.3 指令与配置分离

`PAWCODE.md`/`AGENTS.md` 是给 Agent 的自然语言上下文；JSON 配置是给 PawCode 运行时解析的结构化数据。配置文件不能通过字符串拼接伪装成指令文件，指令文件也不能改变权限决策。

### 2.4 Runtime 边界保持稳定

`AgentRuntime` 只接收已经解析完成的 `systemPrompt` 或上下文快照，不读取文件、不解析 JSON、不判断配置优先级。`PiAiModelAdapter` 继续只负责 PawCode 与 pi-ai 的协议转换。

## 3. 目录与文件约定

### 3.1 配置文件

```text
用户级：~/.pawcode/config.json
项目级：<workspace>/.pawcode/config.json
本地级：<workspace>/.pawcode/config.local.json
```

用户级配置目录和文件由 PawCode 创建时设置为目录 `0700`、文件 `0600`；已有更宽权限时应给出 warning，并在需要保存凭据时拒绝继续。用户级配置用于跨项目的默认模型和个人凭据。

项目级 `.pawcode/` 已被 Git 忽略。`config.local.json` 明确用于本机项目设置，禁止提交；它可以保存本地非敏感覆盖，但不能保存 API Key、Authorization header 或其他供应商凭据。代码必须在错误信息和诊断输出中遮蔽敏感值。

用户级路径不能从项目配置中指定，必须由 PawCode 自己解析。项目级和本地级文件只能位于当前工作区的 `.pawcode` 目录，不能通过配置字段跳转到其他目录。

### 3.2 指令文件

候选文件按目录层级加载：

```text
用户级：~/.pawcode/PAWCODE.md
项目级：<workspace>/PAWCODE.md
项目级：<workspace>/AGENTS.md      # 兼容来源
子目录：<workspace>/<path>/PAWCODE.md
子目录：<workspace>/<path>/AGENTS.md
```

对目标文件或目录 `workspace/src/tools/example.ts`，只加载从工作区根到目标路径父目录之间的指令文件。越接近目标路径的文件优先级越高；同一目录下 `PAWCODE.md` 优先于 `AGENTS.md`。同名来源在同一目录重复出现时只保留一次，并在诊断中说明去重原因。`AGENTS.md` 默认参与读取；用户可以通过 `instructions.includeAgentsMd: false` 关闭兼容来源。

v0.5 第一阶段只对 Agent 当前准备读取、写入或执行命令的路径计算 scoped context；没有明确目标路径时只加载用户级和工作区根级上下文，避免把整个项目所有子目录规则放进每次请求。

## 4. 配置 schema

初始 schema 只覆盖运行时安全且可验证的字段：

```ts
interface PawCodeProjectConfig {
  model?: {
    provider?: string
    baseUrl?: string
    name?: string
    apiKey?: string
  }
  instructions?: {
    files?: string[]
    includeAgentsMd?: boolean
    maxFileBytes?: number
  }
  context?: {
    appendSystemPrompt?: string
    pathRules?: Array<{
      pattern: string
      instructions?: string
      disabledTools?: string[]
    }>
  }
  display?: {
    verboseTools?: boolean
  }
}
```

实际实现必须使用独立的 Zod schema，并拒绝未知字段或提供明确的兼容策略；不能静默接受拼写错误的配置。以下字段禁止进入项目级和本地级配置：

- `model.apiKey`、任何供应商密钥或 Authorization header；
- 可执行任意 Shell 的字符串；
- 能改变 workspace 根目录、`.git` 保护或危险命令拒绝的开关；
- 任意绝对路径形式的指令文件引用；
- 未经定义的 Hook、MCP、Skill 或子 Agent 配置。

`model.apiKey` 只允许出现在用户级 `~/.pawcode/config.json` 中，并且读取、诊断和错误处理都必须使用 redacted 值。v0.5 不读取 `MODEL_API_KEY` 等环境变量；需要临时切换时使用 CLI 显式参数或先修改用户级配置。

## 5. 核心模块规划

建议新增以下模块：

```text
src/context/
├── context-types.ts       来源、文档、路径范围和快照类型
├── instruction-loader.ts  发现、读取、大小限制和来源排序
├── context-resolver.ts    按目标路径合并指令和路径规则
└── context-display.ts     面向 CLI/JSON 的来源与覆盖诊断

src/config/
├── config.ts              最终配置入口和兼容迁移错误
├── config-schema.ts        分层配置 Zod schema
├── config-loader.ts        用户/项目/本地配置发现与解析
└── config-diagnostics.ts   配置来源、覆盖和校验错误
```

模块职责边界：

- `config-loader` 只返回结构化配置和来源，不生成模型 prompt。
- `instruction-loader` 只读取明确允许的 Markdown 文件，不解析其中的命令并执行。
- `context-resolver` 根据当前工作区和目标路径生成不可变 `ResolvedContext`。
- CLI 负责展示诊断；Runtime 只消费 `ResolvedContext.systemPrompt` 和工具限制。
- `PermissionManager` 仍是副作用授权的唯一入口；`disabledTools` 只能收紧工具集合，不能放宽权限或解除硬拒绝。

## 6. 运行时数据流

```text
CLI 参数 / cwd / 目标路径
          ↓
ConfigLoader + InstructionLoader
          ↓
ContextResolver
          ↓
ResolvedContext
  ├── systemPrompt
  ├── disabledTools
  ├── sources[]
  └── diagnostics[]
          ↓
createRuntimeBundle()
          ↓
AgentRuntime / ModelAdapter
```

`systemPrompt` 在新会话开始和每次目标路径变化时计算。它不得作为普通 user message 写入 session history；否则项目规则会被重复保存、压缩和回放，也可能把本地私有规则意外持久化到会话文件。若后续需要记录上下文版本，只保存 source path、内容 hash 和 loader version。

模型请求的 system prompt 组合顺序暂定为：

```text
PawCode 内置安全系统提示
→ 用户级指令
→ 工作区根级指令
→ 目标路径沿途指令
→ 配置生成的受限附加上下文
```

项目上下文不能覆盖内置安全提示。若上下文文件要求绕过权限、访问 workspace 外路径、执行被拒绝命令或泄露密钥，Runtime 必须忽略该要求并继续使用现有安全边界。

## 7. 路径匹配与安全规则

- 所有配置文件和指令文件先通过工作区路径解析，再执行 `realpath`/父目录检查。
- 配置中的路径模式只能是工作区相对 POSIX 路径，禁止 `..` 逃逸、绝对路径和符号链接绕过。
- 模式匹配使用单一实现，建议采用 minimatch 风格但限制为文件路径匹配；不允许执行 Glob 返回工作区外路径。
- 指令文件默认最大 128 KiB，单次解析的总上下文默认最大 512 KiB。
- 文件读取失败、权限不足、格式错误和超过大小限制都必须形成可诊断 warning；不能静默吞掉。
- `config.local.json` 和用户级文件的敏感字段不会出现在 JSON 诊断、错误堆栈或 session 文件中。
- 读取上下文文件时不跟随逃逸到工作区外的符号链接。
- 规则只影响 prompt 和可选的工具收紧；所有写入、命令和 Git 操作仍进入 `ToolRegistry → PermissionManager`。

## 8. CLI 与 JSON 接口

建议新增：

```bash
pawcode --show-context
pawcode --show-context src/tools/example.ts
pawcode --show-config
pawcode --show-config --json
```

人类输出展示：

- 每个来源文件及其优先级；
- 是否启用、跳过或被覆盖；
- 内容字节数和 hash；
- 生效路径范围；
- 配置字段的来源和最终值，敏感字段只显示 `<redacted>`。

JSON 输出使用现有 NDJSON renderer，增加版本 1 的 `context` 和 `config` 事件。stdout 只能包含合法 JSON；诊断错误写 stderr。`--show-context` 不启动模型、不创建 session、不执行工具。

## 9. 会话、压缩和缓存策略

- 默认不把上下文正文保存进 `SessionRecord.messages`。
- 恢复会话时按当前工作区和当前目标路径重新解析上下文；若规则文件变化，诊断中显示 hash 变化。
- ContextCompactor 不摘要项目指令文件，因为它们不属于历史消息；压缩摘要只保留用户对话中形成的决定。
- v0.5 第一阶段不做跨进程内存缓存；可在 `ResolvedContext` 内保存内容 hash，避免同一次请求重复读取。
- 后续若加入缓存，缓存 key 必须包含 workspace realpath、目标路径、配置层级 hash、指令文件 hash 和 loader 版本。

## 10. 错误和兼容策略

- 没有任何配置或指令文件：使用现有默认行为，不报错。
- 单个指令文件读取失败：保留其他来源，输出 warning；根级文件权限错误在 `--show-context` 中显式标红。
- 配置 JSON 语法或 schema 错误：项目级和本地级配置默认使启动失败，避免用户以为规则已经生效；用户级配置错误可在明确提示后回退内置默认值，最终实现需通过测试固定语义。
- `AGENTS.md` 默认兼容读取，并在 `--show-context` 中明确标记为兼容来源；`instructions.includeAgentsMd: false` 可关闭。
- 检测到旧的 `MODEL_*` 环境变量时不读取其值；人类模式给出迁移提示，JSON 模式输出结构化 warning，提示将模型配置迁移到 `~/.pawcode/config.json`。
- 新字段未知时拒绝当前配置文件，不影响其他层的读取结果；错误应指出文件路径、字段路径和修复建议。
- 外部项目已有 `.pawcode` 文件时只读取符合 schema 的文件，不执行其中的脚本或动态配置。

## 11. 测试规划

### 单元测试

- 配置层级的覆盖顺序和来源记录；
- Zod schema 对未知字段、非法模式和敏感字段的拒绝；
- 指令文件按目录层级排序；
- `PAWCODE.md` 与 `AGENTS.md` 的同目录优先级和去重；
- 路径模式、符号链接、`..`、绝对路径和工作区外路径；
- 文件大小限制、读取失败和 warning；
- system prompt 组合顺序和安全提示不可覆盖；
- `disabledTools` 只能收紧工具集合。

### CLI 回归测试

- `--show-context` 不调用模型、不创建会话；
- `--show-config --json` 每行可解析；
- 配置错误不会把密钥写入 stdout/stderr；
- 恢复会话后按当前上下文文件重新解析；
- 既有 v0.4.1 的权限、会话、JSON、压缩和错误恢复测试全部继续通过。

### 验收标准

- 新项目无需配置文件即可保持 v0.4.1 行为。
- 同一项目不同目标路径只加载对应目录链上的上下文。
- 配置和指令来源可通过 CLI 完整解释。
- 上下文正文不会进入 session history、session JSON 或错误日志。
- 项目上下文不能绕过现有 ToolRegistry、PermissionManager、workspace 和危险命令保护。
- 运行 `pnpm format:check && pnpm check && pnpm test && pnpm build` 全部通过。

## 12. 分阶段实施计划

动态上下文的后续 Runtime 接入细节见 [v0.5 动态上下文设计](./v0.5-dynamic-context-design.md)。

1. **阶段 A：类型和读取层**
   - 新增 context/config 类型、schema、加载器和路径安全测试。
2. **阶段 B：解析与诊断**
   - 实现来源合并、路径规则、hash、warning 和 CLI/NDJSON 诊断。
3. **阶段 C：Runtime 接入**
   - 在 CLI 创建 Runtime bundle 前解析上下文；只向 Runtime 注入最终 system prompt 与收紧后的工具集合。
4. **阶段 D：回归与文档**
   - 完成全量验证，更新 README、continuation context 和版本验收记录。

已确认的实现决策：

1. `AGENTS.md` 默认兼容开启；`instructions.includeAgentsMd: false` 可关闭。
2. 项目级配置首版包含 `display` 字段，至少支持 `display.verboseTools`，并沿用现有 CLI 显式参数优先级。
