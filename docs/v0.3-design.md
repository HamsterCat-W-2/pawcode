# PawCode v0.3 技术设计

## 1. 目标

v0.3 将 PawCode 从只读项目分析 Agent 升级为可以安全修改代码、运行命令并验证结果的编程 Agent，同时继续保持 PawCode Domain 与 `pi-ai` 的 Adapter 边界。

本版本包含：

1. Token 用量、成本与 stop reason 展示。
2. `allow`、`ask`、`deny` 权限决策。
3. `write_file` 与 `apply_patch` 文件编辑工具。
4. `run_command` 无 Shell 命令工具。
5. `git_diff` 变更检查工具及修改后验证工作流。

会话持久化、上下文压缩、MCP 和子 Agent 不属于 v0.3。

## 2. 架构约束

```text
pi-ai AssistantMessage
        ↓ PiAiModelAdapter
ModelResponse（usage / stopReason）
        ↓
AgentRuntime
        ↓ ToolCall
ToolRegistry
        ↓ PermissionRequest
PermissionManager ── allow / ask / deny
        ↓ allow
Tool.execute()
        ↓
ToolResult → 下一轮模型
```

- `AgentRuntime`、CLI 和工具不得导入 `pi-ai` 类型。
- `providerData` 继续保存原始供应商消息，保证多轮调用可重放。
- 所有产生副作用的工具都必须声明权限请求，不能绕过 `ToolRegistry`。
- 默认安全：缺少权限管理器或非交互环境没有显式允许规则时，写入和命令执行均拒绝。
- 不自动提交、推送、删除或覆盖工作区外的数据。

## 3. 模型统计信息

在 PawCode Domain 中定义供应商无关的 `ModelUsage`：

```ts
interface ModelUsage {
  inputTokens: number
  outputTokens: number
  cacheReadTokens: number
  cacheWriteTokens: number
  totalTokens: number
  cost?: {
    input: number
    output: number
    cacheRead: number
    cacheWrite: number
    total: number
  }
}
```

`PiAiModelAdapter` 负责从 `pi-ai Usage` 显式转换。Runtime 汇总一次 Agent run 内所有模型轮次的用量，最终 `completed` 事件携带累计用量和最后一个 stop reason。CLI 只负责格式化显示。

## 4. 权限模型

### 4.1 请求

副作用工具在执行前生成：

```ts
interface PermissionRequest {
  capability: 'write' | 'execute'
  tool: string
  description: string
  resource: string
}
```

`resource` 是规则匹配使用的稳定值：写工具使用工作区相对路径，命令工具使用规范化后的“命令 + 参数”。

### 4.2 决策

- `allow`：命中启动参数或本次会话允许规则，立即执行。
- `ask`：交互模式中询问用户，可允许一次、允许本会话同类资源或拒绝。
- `deny`：危险命令、缺少确认器或用户拒绝时不执行。

CLI 提供：

- `--allow-write`：本次进程允许工作区内写入。
- `--allow-command <command...>`：允许命令前缀，可重复传入。

交互确认不会写入磁盘；“本会话允许”只存于内存。`run_command` 对 `rm`、`sudo`、`shutdown`、`reboot`、`mkfs`、`dd` 以及破坏性 Git 子命令执行硬拒绝，显式允许规则也不能覆盖。

## 5. 文件编辑

### 5.1 `write_file`

参数：相对路径和完整内容。支持创建父目录与覆盖文件，单次内容不超过 1 MiB。

### 5.2 `apply_patch`

采用确定性的文本替换协议，而不是让 Runtime 解析供应商私有 diff：

```json
{
  "path": "src/example.ts",
  "old_text": "旧文本",
  "new_text": "新文本",
  "replace_all": false
}
```

默认要求 `old_text` 在文件中只出现一次；出现零次或多次都返回错误。`replace_all` 必须显式设置才能替换多处。

### 5.3 路径安全

- 只接受相对路径。
- 词法路径必须位于工作区内。
- 已存在目标使用 `realpath` 校验。
- 新目标校验最近的已存在父目录，阻止借助父级符号链接逃逸。
- 文件工具禁止修改 `.git` 元数据。
- 拒绝覆盖目录和超过大小限制的文件。

## 6. 命令执行

`run_command` 参数为：

```json
{
  "command": "pnpm",
  "args": ["test"],
  "cwd": ".",
  "timeout_ms": 120000
}
```

- 使用 `child_process.spawn(command, args, { shell: false })`。
- `cwd` 必须解析到工作区内的真实目录。
- 捕获 stdout、stderr 和退出码。
- 支持超时和 Runtime 的 `AbortSignal`。
- ToolRegistry 统一执行最终输出截断。

## 7. Git 与验证工作流

`git_diff` 是只读工具，返回 `git status --short` 和工作区 diff。Agent 的系统提示要求：

1. 修改前读取相关文件。
2. 使用 `apply_patch` 做小改动，完整创建文件时使用 `write_file`。
3. 修改后调用 `git_diff`。
4. 根据 `package.json` 使用 `run_command` 执行格式、类型、测试和构建。
5. 失败时继续修复；未经用户明确要求不提交或推送。

## 8. 错误与取消

- 权限拒绝以可读的工具错误返回模型，不终止整个 Agent 会话。
- 参数校验、路径越界、命令启动失败和超时均由 ToolRegistry 转换为统一错误文本。
- 模型请求和命令执行共享当前 run 的 `AbortSignal`。
- 命令取消先发送 `SIGTERM`；本版本不使用 Shell，因此不会创建 Shell 子进程链。

## 9. 测试与验收

必须覆盖：

- usage 与 stop reason 的 Adapter 转换和 Runtime 累加。
- `allow`、`ask`、`deny`，包括非交互默认拒绝与危险命令硬拒绝。
- 新建、覆盖、单处补丁、多处歧义和路径/符号链接逃逸。
- 命令成功、非零退出、超时和工作目录越界。
- Git diff 能看到未提交改动。
- 原有只读工具和流式多轮测试继续通过。

交付前运行：

```bash
pnpm format:check
pnpm check
pnpm test
pnpm build
```
