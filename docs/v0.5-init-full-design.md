# v0.5 `/init --full` 技术设计

## 1. 背景与目标

当前 `/init` 是快速模式：只读取有限目录中的高评分元数据文件，并受单文件和总输入大小限制。它适合小型项目，但大型项目可能因为截断或候选文件未进入快照而缺少模块级信息。

`/init --full` 的目标是通过“完整索引、分块摘要、最终汇总”提高大型项目的覆盖率，同时保持以下约束：

- 不把整个仓库一次性放入单个模型请求。
- 不把密钥、二进制文件、生成物和被忽略文件发送给模型。
- 不改变现有 `PermissionManager`、`WorkspaceFiles` 和 `PAWCODE.md` 写入安全策略。
- 中途失败时不写入不完整的 `PAWCODE.md`。

## 2. 范围与非目标

### 范围

- 交互命令支持 `/init --full`。
- 构建完整的安全文件索引和目录树。
- 按文件组或模块分块，分别生成结构化摘要。
- 汇总所有摘要并生成最终 `PAWCODE.md`。
- 展示扫描、跳过、截断、摘要失败和最终写入诊断。

### 非目标

- 不保证读取所有文件原文；完整模式保证的是项目结构和模块摘要覆盖率。
- 不执行项目命令，不安装依赖，不修改 Git 元数据。
- 不自动覆盖已有 `PAWCODE.md`。
- 不在本阶段实现后台任务、并发 Agent 或持久化摘要缓存。

## 3. Module 与 Seam

将现有 `ProjectInitializer` 保持为 CLI 使用的深模块，并在其内部增加两个实现阶段：

```ts
interface ProjectInitializer {
  inspect(mode?: 'quick' | 'full'): Promise<ProjectSnapshot>
  summarize(snapshot: ProjectSnapshot): AsyncIterable<ProjectSummaryEvent>
  generate(summaries: ProjectSummary[]): Promise<string>
  write(content: string, signal?: AbortSignal): Promise<string>
}
```

CLI 只负责解析 `/init` 参数、展示进度和调用权限确认；扫描、分块、模型流收集、敏感过滤和失败聚合都留在 `ProjectInitializer` 实现内，保持维护 Locality。

模型仍通过 `ModelAdapter` seam 调用，不让 `ProjectInitializer` 依赖 `pi-ai` 类型或供应商协议。

## 4. 完整扫描流程

```text
/init --full
  ↓
安全文件索引 + 完整目录树
  ↓
敏感/二进制/忽略路径过滤
  ↓
按目录和文件大小形成 Chunk
  ↓
每个 Chunk 生成结构化模块摘要
  ↓
汇总摘要生成 PAWCODE.md
  ↓
预览 + PermissionManager
  ↓
WorkspaceFiles 原子写入
```

### 文件索引

- 复用现有 `WorkspaceFiles` 的工作区、符号链接和默认生成物保护。
- 复用 `.gitignore` 过滤逻辑，并保留敏感路径过滤。
- 对文本文件记录相对路径、字节数、行数和可读性；二进制文件只记录“已跳过”的诊断，不读取内容。
- 目录树使用相对 POSIX 路径，排序稳定，保证同一项目重复运行结果可比较。

### 分块策略

- 优先按一级、二级目录聚合，避免把同一模块拆到不同摘要中。
- 单个 Chunk 有独立的字节预算和文件数量上限。
- 超大文件按行范围拆分，并在摘要输入中标注分片范围。
- 单个文件或模块失败不阻断其他 Chunk；最终汇总时明确列出失败项。
- Chunk 顺序稳定，按目录路径和文件路径排序，避免模型结果因文件遍历顺序变化。

## 5. 模型协议

每个摘要请求只接收一个 Chunk，要求输出结构化 Markdown 或内部结构化对象，至少包含：

- 模块职责
- 入口和关键文件
- 主要数据流或依赖关系
- 常用开发命令（仅在事实中出现时记录）
- 测试和构建方式
- 未确认事项

最终汇总请求只接收 Chunk 摘要、项目目录树和快速模式元数据，不重新接收全部源码。模型必须：

- 只输出 `PAWCODE.md` Markdown
- 不编造未出现在摘要中的命令和架构
- 不输出 API Key、Token、密码或私钥
- 以一级标题开头

## 6. 预算、取消与失败

- 总扫描量、单文件读取量、Chunk 数、单 Chunk 字节数和摘要输出长度都必须有上限。
- 达到预算时停止新增 Chunk，并在诊断中说明未处理文件数量。
- `/init --full` 使用交互运行的 `AbortSignal`；取消时停止后续摘要请求，不写入目标文件。
- 任意 Chunk 摘要失败时继续处理其他 Chunk，但最终文档必须标注摘要不完整。
- 最终汇总失败、输出为空、格式非法或敏感检测命中时，保留已有文件并拒绝写入。

## 7. 进度与诊断事件

人类输出示例：

```text
/init --full
扫描项目：128 个文件，跳过 14 个
生成摘要：3/8 个模块
摘要失败：docs/legacy（读取超时）
生成完成：覆盖 7 个模块，仍有 1 个模块未完成
```

后续可将进度投影为 NDJSON 事件，例如 `init_scan_started`、`init_chunk_completed`、`init_chunk_failed`、`init_generation_completed`。本阶段先保持 CLI 内部事件，不污染 Session 历史。

## 8. 安全设计

- 全部读取路径必须经过 `WorkspaceFiles`。
- 所有写入仍然通过 `PermissionManager` 的 `write` capability。
- `PAWCODE.md` 已存在时直接停止，不覆盖用户规则。
- 模型输入和输出都执行敏感路径、凭据模式和私钥检测。
- 诊断只输出相对路径、数量和失败原因，不输出敏感文件内容。
- 不把完整源码写入 `PAWCODE.md`，避免生成文件膨胀和意外泄露实现细节。

## 9. 测试计划

- 多目录项目按稳定顺序形成 Chunk。
- 超大文件按分片范围读取。
- 总预算和 Chunk 预算达到上限时生成可见诊断。
- `.gitignore`、默认忽略目录、符号链接和敏感文件不会进入模型输入。
- Chunk 摘要部分失败时仍能完成其他摘要并标记不完整。
- 用户取消、模型失败、空响应、非法 Markdown 和敏感输出均不写入文件。
- 已有 `PAWCODE.md` 不会被覆盖。
- 端到端验证 `/init --full` 生成文件后可被 `resolveContext()` 加载。

## 10. 分阶段实现

1. 抽取通用安全文件索引和诊断模型。
2. 实现稳定分块器和预算控制。
3. 实现 Chunk 摘要模型调用与取消。
4. 实现最终汇总和安全输出校验。
5. 接入交互 `/init --full` 及进度展示。
6. 补充测试、README 和 continuation context 文档。
